Movicon NExT, taken apart

How the open Petrogas project is built, stored and executed, read from its files on disk, the installed platform, the runtime logs and the live designer and runtime UI. The second half maps each part onto a smaller, sturdier design in Rust.

1. The running system

Movicon NExT is a .NET “platform” of cooperating processes. The project is loaded by a WPF runtime, which launches a separate I/O server and talks to it over OPC UA. Every service module (scheduler, alarm dispatcher, recipes) is modelled as its own OPC UA server application with its own endpoint and SQL catalog.

2. Anatomy of a project

The .UFProject file is a WCF DataContract XML manifest: culture, theme, main screen GUID, sampling intervals (fast 500 ms, slow 5000 ms, publishing 250 ms), per-screen tile colours and the project type (WebHMI). Every other module is a folder holding one document. Most of those documents are serialized ADO.NET DataSets: an inline XSD schema followed by table rows, which is how DevExpress XPO’s InMemoryDataStore persists objects.

3. Tags, drivers and the data path

A tag is a row in UFUATag with about 40 columns. Its connection to the field is one pipe-delimited string, parsed by the driver at load time:

Name             FM_01_MassFlow
DataType         9            (float)
DynamicSettings  ModbusTCP.Station=Flow_Meter_1|LinkType=0|FC=5|SA=247|File=0
HistorianSettings FM01        (matched by name)
NodeId           f1ecf2f8-e820-4ba9-afe2-5216926580a3   → OPC UA ns=2;g=…

From device to pixel

  • The driver groups adjacent addresses into 15 jobs and polls them every 500 ms over one TCP channel.
  • Values land in the OPC UA address space (2:Tags/2:FM_01_Density), with quality and timestamps.
  • The runtime subscribes per visible screen, with 250 ms publishing. disableWhenNotUsed drops items 30 s after a screen closes.
  • Screen controls resolve a SVGReferenceId → .references entry → NodeId, then format the value (#0.000000, unit kg/m³).
  • Bad quality draws a red border and a warning triangle, which is what the live Manifold screen shows now, because the 169.254.100.100 gateway is unreachable from this PC.

5. What the UI shows

Designer

  • Visual Studio–style dock layout (the layout is saved in Documents/Petrogas.layout): project explorer on the left, document tabs in the centre, property grid on the right, ToolBox and Symbol Library as side tabs, and Animations / XML / Script / System Log / Commands panels along the bottom.
  • The project tree mirrors the folder layout: Client Configuration, Logic, Schedulers, Reports, Screens, Parameters, Texts, Cross Reference, Events, Recipes, I/O Data Server (Data Structure, Tags List, Settings, Drivers, Alarms, Historians, Data Loggers, Engineering Units, Views, Redundancy), Users.
  • Each tool is a separately loaded plug-in DLL (DesignPlugins, DocumentManagers, Toolbox, Managers).
  • Animation is a fixed catalogue applied per object: Back Color, Border Color, Visibility, Blink, Filling, Height, Width, Scale, Rotation, Move X, Move Y.
  • The Script panel reads “No supported on WebHMI”: choosing the web project type removes C#/VB scripting.
  • Selecting and zooming marked the Manifold tab as modified (*), so view state and document state are not separated.

Runtime

  • Full-screen, borderless WPF window started with -start -skin=VS2017Dark -nosplash -debug.
  • Manifold is a 1920×1080 canvas of custom Pipeline polylines, valve and meter symbols, and value displays in mTon/hr. Navigation buttons open the per-meter trend screens.
  • Opening “HFO Trend & Log” took about 10 s and then hung on “Fetching Data…”. The historian’s connection string names a SQL instance on the original engineering PC that doesn’t exist here.
  • The trend/log view is a DevExpress chart plus grid with time presets (Minute … All), a 3,600-record cap and a 1753–9999 default range.

7. The same system in Rust

The core idea: one typed source model, one compile step, one runtime process. Movicon’s complexity mostly comes from keeping many representations and processes in agreement at run time. Rust’s type system and a build step can settle that agreement before the plant ever sees it.

Movicon NExT todayRust designWhat it buys
XPO DataSets with inline XSD; a 40-column tag row; config buried in pipe strings like Station=…|SA=247serde structs with enums (Address::Modbus{station, kind, addr}); defaults omitted from files; JSON Schema generated for the editorDiffable, mergeable projects. Invalid addresses fail to parse instead of failing at run time.
14 files per screen, synced by the designerOne SVG with data-bind attributes plus one TOML sidecar; derived artefacts produced only by movi buildOne source of truth, roughly 10–100× less on disk
References checked at run time, logged as errorsThe build resolves every tag, station, screen and historian reference and rejects dangling ones with file:line diagnosticsRemoves the “station does not exist” and “missing NodeId” class of faults
Startup of 50 s: process spawn, CLR, plug-in loadingStatic binary; bundle memory-mapped with rkyv; drivers start as tasksSub-second start; a plant restart becomes cheap
Tags exposed through an OPC UA server, consumed by the local HMI over net.pipeLock-free tag arena indexed by u32; tokio::sync::broadcast change bus coalesced per client tick; async-opcua server for outside consumers onlyFewer copies and serializations per value; memory in the tens of MB for this project
Driver DLLs loaded in-process by reflectiontrait Driver (async read/write/browse); each station a supervised task with backoff; optional out-of-process drivers over a stdio protocol for vendor SDKs (AGLink, PVI)One misbehaving station or panic can’t take the server down
SafeData*.xml fallback, SQL schema created at first runAppend-only local journal (redb or SQLite WAL), forwarded in batches with sqlx; migrations shipped with the binaryNo data loss when SQL is down, and no first-run CREATE DATABASE failures
Plain-text connection stringssecret://historian references resolved from OS keychain, environment or a vault at start; never written to project filesProjects and backups can be shared safely
C#/VB scripts (WPF only), expression stringsRhai for simple expressions; WASM components (wasmtime) with fuel and memory limits for logicSame scripts on desktop, web and Linux; a runaway script can’t freeze the HMI
WPF runtime plus a separate HTML5 clientOne web renderer (SVG + TypeScript, or Leptos) over WebSocket; Tauri for kiosk and editorAnimations and controls implemented once

Rust fixes the architecture, not the breadth. Movicon ships 43 drivers, certified OPC UA, report designers and years of field fixes. A clone becomes competitive for projects like Petrogas (Modbus, trends, a few screens) long before it matches the whole product. Plan phases 1–4 against this one project and measure before widening scope. A Movicon-compatible importer is fine; avoid shipping Progea’s encrypted symbol library or copying its look.
